# 性能檢查與量測腳本（Phase 7 / T045/T055–T057/T062/T063）

## 前置
- 啟動：`npm run dev`，瀏覽 http://localhost:3000。
- 資料集：
   - 50/500 提示詞：於 `Prompts/Perf50`、`Prompts/Perf500` 放置含 frontmatter 的 Markdown（可複製現有檔案並重命名）。
   - 搜尋截斷：準備 1000 筆以上提示詞（可複製 Perf500 兩份並調整標題）。
- 設定：
   - `INBOX_PAGE_SIZE` 可設定觀察分頁開銷。
   - 如需乾淨環境，清除 `db.json` 或使用 `DEFAULT_ROOT` 指向臨時資料夾。

## 量測項目與方法

- **SC-001 / SC-008 啟動時間**：
   1) 使用 50/500 資料集啟動頁面，開 DevTools Performance。
   2) 量測「載入→列表可互動」時間；目標：50 筆 < 2s，500 筆 < 5s。

- **SC-002 草稿→轉正耗時**：
   1) 在收件匣建立草稿，執行轉正流程並寫檔。
   2) 以 Performance 標記從點擊轉正到成功提示時間，重複 3 次取平均，目標 < 30s（預期更短）。

- **SC-003 精簡/完整複製耗時**：
   1) 於提示詞頁點「複製完整」「複製精簡」。
   2) 量測點擊到剪貼簿 API 完成時間，目標 < 150ms。

- **SC-004 搜尋 p95**：
   1) 在 1000+ 筆資料下搜尋常見關鍵字。
   2) 以 Performance 量測鍵入→結果渲染時間，計算 p95 需 ≤ 2s；超過 1000 筆需回傳截斷旗標。

- **SC-006 外部修改提示通知**：
   1) 開啟任一提示詞。
   2) 於檔案系統修改同檔案 mtime/內容。
   3) 5 秒內應觸發重新載入/衝突提示；紀錄是否達標。

- **SC-007 片語搜尋/插入耗時**：
   1) 開啟片語 Drawer，搜尋並點擊插入。
   2) 量測從搜尋輸入到插入完成的總耗時，目標 ≤ 10s。

- **SC-011 Pin 收合動畫**：
   1) 切換 Pin = OFF，點擊提示詞觸發收合。
   2) 以 Performance 量測動畫結束時間，目標 150–250ms。
