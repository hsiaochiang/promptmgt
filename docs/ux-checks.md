# UX 檢查與觀察（Phase 7 / T055–T060）

## 前置
- 以 `npm run dev` 啟動；使用 50/500 筆資料集與 1000+ 筆截斷場景各跑一次。
- 記錄工具：螢幕錄影 + 簡短備註；若可，附上 DevTools Performance trace。

## 時間格式與顯示（FR-034/FR-035 | T073/T079）
- 檢查列表（專案/提示詞）顯示格式 `MM/DD HH:mm`，編輯器標題列顯示 `HH:mm` 且與後端 ISO+08:00 時間一致。
- 若顯示異常，重載同筆資料或重新儲存（API 會套用 `toIsoWithOffset()`），再確認 UI 格式化是否恢復；必要時參考 perf-checks.md 的檔案抽樣步驟。

## 檢查項目

## 無障礙（a11y）最小檢核（T066）

- **Tabs（Topbar）**：
   - Tab 鍵可聚焦到 Tabs；僅當前啟用的 tab 需為 `tabIndex=0`，其餘為 `-1`。
   - 左右方向鍵可在 Tabs 間移動焦點；Enter/Space 可啟用焦點所在 tab。
   - `role=tablist/tab/tabpanel`、`aria-selected`、`aria-controls` / `aria-labelledby` 對應正確。

- **Confirm Modal**：
   - 開啟後焦點落在可操作元件且不會跑出 modal（focus trap）。
   - Esc 可關閉；關閉後焦點回到觸發按鈕。

- **Snackbar Undo**：
   - Undo/Close 可被鍵盤聚焦並可操作；倒數期間不阻斷其他互動。

- **RootPathAlert**：
   - 導向設定頁的連結文字可理解（非僅圖示），可用鍵盤觸發。

- **錯誤訊息**：
   - 錯誤需可被輔助工具讀取（避免只用顏色區分）；文案具體可操作（告知如何修復）。

- **SC-009 首次體驗成功率**：
   - 清空 `db.json` 與 `Prompts/`，或指向臨時 rootPath。
   - 任務：設定 rootPath → 新增草稿 → 轉正 → 編輯儲存 → 插入片語。
   - 5 次自測或 5 名使用者，成功率目標 ≥ 80%；記錄阻塞點（路徑缺失、API 錯誤、UI 卡頓）。

- **SC-010 互動卡頓/動畫遲滯**：
   - 在 100+、1000+ 筆資料下，觀察列表切換、開啟提示詞、複製、搜尋。
   - 若有 > 200ms 可感卡頓，記錄操作與 trace；目標卡頓回報率 < 10%。

- **SC-016 Inbox 淨空可見性**：
   - 完成 Inbox 工作後，淨空狀態文案/行動是否清晰；避免繼續工作混淆。

- **SC-017 Undo/Redo 易發現性**：
   - 在編輯器試用 Undo/Redo，確認快捷鍵可用、可被注意到，且不破壞焦點。

- **SC-018 Accordion 快捷鍵**：
   - 測試展開/收合快捷鍵是否存在且文件化，行為一致、無錯位。

- **SC-019 錯誤敘述可理解性**：
   - 觸發常見錯誤（檔案寫入失敗、搜尋截斷、衝突提示），文案需行動導向、避免技術行話。

- **搜尋截斷與空態文案**：
   - 超過 1000 筆搜尋結果時，顯示橫幅「僅顯示前 1000 筆，請收斂搜尋條件（篩選專案/狀態或縮小關鍵字）」並保留現有結果。
   - 查無結果時顯示「沒有符合結果，請縮小搜尋條件或檢查關鍵字」並提供重新搜尋/清除篩選的操作提示。
   - 收件匣超過 100 筆時持續顯示整理提示「草稿超過 100 筆，請使用搜尋或分頁逐步整理，避免介面過載。」；當頁面為空仍顯示空態「沒有符合條件的草稿」。

- **SC-020 視覺延遲回饋**：
   - 在長操作（搜尋 1000+、大量載入）期間是否顯示忙碌/進度指示，避免誤判為卡死。
