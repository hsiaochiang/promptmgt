# Feature Specification: 本機提示詞管理系統（雙層儲存＋UI Prototype 對應）

**Feature Branch**: `001-local-prompt-manager`  
**Created**: 2025-12-20  
**Status**: Implemented  
**Input**: User description: "建立一個本機執行（Localhost only）的個人提示詞管理系統，採雙層儲存架構（Markdown 檔案 + LowDB JSON 資料庫），介面依 UI Prototype 支援收件匣草稿→專案歸檔→片語組裝工作流。"

## Clarifications

### Session 2025-12-20

- Q: 外部工具修改檔案且本地有未保存編輯時，應用如何處理？ → A: 偵測後彈窗，提供「載入外部版本 / 保留目前編輯 / 檢視差異後再決定」三選，避免誤覆蓋並讓使用者掌控
- Q: 是否允許自動對外連線或遙測？ → A: 允許匿名遙測與更新檢查，預設開啟
- Q: 自動儲存間隔多久執行一次？ → A: 2 秒（草稿與提示詞同頻率），無輸入時暫停計時，恢復輸入再計時
- Q: 如何設定或修改根路徑？ → A: 透過設定頁輸入並儲存 rootPath，缺路徑時在 RootPathAlert 提供導向連結
- Q: 是否允許直接新增/刪除專案、提示詞、片語？ → A: 需提供 UI 與 API 入口，支援新增、編輯、刪除與即時刷新列表

### Session 2025-12-21

- Q: 提示詞列表的 Pin（釘住）預設與持久化行為為何？ → A: 預設 Pin = ON，並以 localStorage 跨專案、重整持久化；使用者可手動切換為 OFF 以獲得更大編輯區。
- Q: 本機資料（草稿/提示詞/設定）預設的存放安全與目錄策略為何？ → A: 依作業系統使用者權限存放於使用者目錄下的隱藏資料夾，無額外應用層加密。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 收件匣快速草稿捕捉 (Priority: P1)

使用者打開應用即可在收件匣輸入 Markdown 草稿，系統自動儲存，避免遺失靈感，稍後再決定分類。

**Why this priority**: 低摩擦捕捉是整個系統的入口，若無法快速落筆，後續歸檔與組裝皆失去意義。

**Independent Test**: 僅啟用收件匣與自動儲存機制；流程「開啟 → 輸入 → 關閉 → 重開」能完整保留內容。

**Acceptance Scenarios**:

1. **Given** 收件匣為空，**When** 使用者輸入草稿文字，**Then** 系統於輸入時自動儲存，未按保存也不會遺失內容
2. **Given** 收件匣已有草稿，**When** 使用者關閉並重開應用，**Then** 草稿內容與最後編輯時間仍可復原顯示
3. **Given** 收件匣有多筆草稿，**When** 使用者查看列表，**Then** 草稿依最後編輯時間排序並顯示前 50 字預覽
4. **Given** 使用者在草稿編輯中貼上大段文字，**When** 系統處理內容，**Then** 介面顯示載入指示且不中斷編輯
5. **Given** 使用者選擇某草稿，**When** 點擊「刪除草稿」，**Then** 該草稿自列表移除且數量更新

---

### User Story 2 - 專案歸檔與列表總覽 (Priority: P1)

使用者可將草稿轉正為正式提示詞，選擇專案、標題、類型、狀態、模型與標籤；專案列表顯示狀態與提示詞數量，支援檢視進行中與規劃中專案。

**Why this priority**: 專案歸檔提供結構化管理，讓提示詞不再分散；是從草稿到可用資產的關鍵步驟。

**Independent Test**: 僅需收件匣與專案清單；流程「草稿轉正 → 專案列表更新 → 檔案生成」可獨立驗證。

**Acceptance Scenarios**:

1. **Given** 收件匣有草稿，**When** 使用者點擊「轉正」並填入標題、選專案、標籤、狀態，**Then** 草稿自收件匣移除，在該專案資料夾生成對應 Markdown 檔
2. **Given** 專案列表含多個專案，**When** 使用者切換專案狀態（進行中/規劃中/已結案），**Then** 列表即時反映分區並保留提示詞計數
3. **Given** 使用者需要新增專案，**When** 於專案列表點擊「新增」並輸入名稱，**Then** 新專案即加入列表且可被選取；若名稱重複需提示
4. **Given** 使用者管理專案，**When** 於專案列表點擊「編輯」或「刪除」，**Then** 對應專案被更新或移除並刷新提示詞計數
5. **Given** 使用者選取某專案，**When** 進入專案視圖，**Then** 看到該專案提示詞列表、更新時間與標籤摘要
6. **Given** 專案資料夾被外部移動或刪除，**When** 應用載入專案，**Then** 顯示路徑失效提示並提供重新定位或移除選項
7. **Given** 使用者未經草稿流程，**When** 於頂部操作直接新增提示詞，**Then** 生成空白提示詞檔並選取進入編輯
8. **Given** 使用者清理提示詞，**When** 點擊「刪除提示詞」，**Then** 檔案移除並刷新專案計數與列表
9. **Given** 提示詞列表，**When** 使用者切換 Pin 為 OFF 並點選提示詞，**Then** 列表自動收合並將寬度讓給編輯區；再點左欄同專案或按 Alt+L 可召回且保留 scroll/選取
10. **Given** 提示詞列表，**When** 使用者開啟三點選單或批次勾選，**Then** 可執行重新命名、複製/另存為、移動、歸檔、刪除；危險動作在清楚區隔處理

---

### User Story 3 - Markdown 編輯與精準複製 (Priority: P1)

使用者在右側工作區以 Markdown 編輯提示詞，查看語法預覽，並可一鍵複製「完整內容（含 Frontmatter）」或「精簡內容（去除元數據）」供貼到 AI 工具。

**Why this priority**: 編輯與複製是每日操作；精簡複製降低貼到模型時的摩擦，完整複製保留上下文。

**Independent Test**: 僅需編輯器與複製按鈕；流程「開啟提示詞 → 編輯 → 預覽 → 複製精簡版」可單獨驗證。

**Acceptance Scenarios**:

1. **Given** 使用者開啟提示詞，**When** 輸入 Markdown（標題、列表、程式碼區塊），**Then** 編輯區顯示語法高亮，預覽正確渲染
2. **Given** 提示詞含 Frontmatter，**When** 使用者點「精簡複製」，**Then** 只複製內容本體（無 YAML/標題/標籤），並顯示已複製提示
3. **Given** 提示詞含元數據，**When** 使用者點「完整複製」，**Then** 將 Frontmatter + 本體複製到剪貼簿
4. **Given** 使用者在編輯中，**When** 使用者按快捷鍵保存或應用自動保存，**Then** 本地檔案更新且顯示最後儲存時間
5. **Given** 右側編輯頁，**When** 使用者切換「專注編輯」模式，**Then** 中欄隱藏且右側最大化；再次切換恢復原寬度與游標位置
6. **Given** 提示詞前言區塊，**When** 進入任一提示詞頁，**Then** 前言 accordion 預設收合（顯示標題/摘要），展開/收合不影響下方編輯器內容與游標
7. **Given** 右側標題列，**When** 使用者滾動內容，**Then** 標題列保持 sticky，顯示儲存狀態與快捷（複製/歸檔/更多）

---

### User Story 4 - 片語剪貼簿插入與統計 (Priority: P2)

使用者在編輯器旁的片語庫搜尋或點擊常用片語，內容即插入游標位置，並記錄使用次數以便排序與決策。

**Why this priority**: 提升組裝效率，雖非入口流程，但能大幅減少重複輸入。

**Independent Test**: 僅需片語庫與編輯器；流程「建立片語 → 搜尋 → 插入 → 查看使用次數」可獨立驗證。

**Acceptance Scenarios**:

1. **Given** 片語庫有項目，**When** 使用者在搜尋框輸入關鍵字，**Then** 列表僅顯示匹配片語
2. **Given** 使用者編輯提示詞，**When** 點擊片語項目，**Then** 片語內容插入當前游標位置
3. **Given** 片語被多次使用，**When** 使用者查看片語詳情，**Then** 顯示使用次數與最後使用時間
4. **Given** 使用者新增片語名稱與既有名稱重複，**When** 提交表單，**Then** 系統阻止並提示更名或合併
5. **Given** 使用者維護片語，**When** 於片語面板點擊「新增/編輯/刪除」，**Then** 對應片語被建立、更新或移除並即時反映列表
6. **Given** 右側工具列，**When** 使用者點擊「常用片語」按鈕或按 Alt+S，**Then** 片語 Drawer 從右側滑出（overlay/push 不重新 mount 編輯器），Esc/overlay 可關閉，插入後游標留在插入點

---

### User Story 5 - 佈局與操作效率 (Priority: P1)

**Why this priority**: 最大化主要編輯區並降低滑鼠/視線移動成本，支援多工與鍵盤工作流。

**Independent Test**: 僅需 UI 交互即可驗證（無後端依賴）：拖曳寬度持久化、Pin 收合/召回、專注模式、快捷鍵與 Undo 提示。

**Acceptance Scenarios**:

1. **Given** 三欄佈局，**When** 使用者拖曳分隔線，**Then** 寬度即時變更且存入 localStorage，重新整理仍維持設定
2. **Given** Pin = OFF，**When** 點選提示詞，**Then** 列表 150–250ms 內收合；按 Alt+L 或點左欄同專案可叫回並保持 scroll/選取狀態
3. **Given** 右側工具列，**When** 使用者按 Alt+P/Alt+L/Alt+N/Alt+Shift+N/Ctrl+K/Ctrl+Shift+C，**Then** 觸發對應 Pin/列表顯示/新增提示詞/快速草稿/全域搜尋/精簡複製；不得與常見瀏覽器快捷鍵衝突
4. **Given** 危險操作（刪除/移動/歸檔），**When** 使用者執行，**Then** 彈出確認＋ snackbar 顯示 `已刪除/已移動/已歸檔` 並提供 5–10 秒 Undo
5. **Given** 全站字級放大 +2px，**When** 瀏覽列表/表單/標籤/按鈕，**Then** 無裁切或行高擁擠，符合 WCAG Text Spacing

### Edge Cases

- 當收件匣草稿超過 100 筆時：啟用分頁（預設 50/頁，可配置），搜尋需跨頁；顯示整理提示文案以避免介面過載
- 當提示詞標題含檔案系統禁用字元（/ \ : * ? " < > |）：系統自動轉換為安全檔名並顯示實際儲存名稱
- 當外部工具修改 Markdown 檔且與當前編輯衝突：彈出提示提供載入外部版本、保留目前編輯、檢視差異後再決定
- 當 YAML Frontmatter 損壞或缺失：降級以純文字顯示內容，標記為需修復並允許重新保存為有效格式
- 當應用啟動時找不到設定的根路徑：提示選擇新路徑或建立預設根目錄，再載入資料
- 當搜尋結果超過 1000 筆：僅顯示前 1000 筆並提示收斂條件
- 當刪除專案或提示詞後：列表與計數需同步刷新，避免殘留選取狀態或計數不一致
- 當設定頁尚未填寫 rootPath：RootPathAlert 需提供導向設定頁的行動入口

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須提供收件匣草稿工作區，允許未選專案即可輸入與編輯 Markdown 草稿並自動儲存
- **FR-002**: 系統必須在使用者輸入過程自動保存草稿與提示詞（間隔 2 秒，無輸入時暫停，恢復輸入後重新計時），並顯示最後保存時間
- **FR-003**: 系統必須提供草稿「轉正」流程，包含設定標題、專案、類型、狀態、模型與標籤，並移除原草稿
- **FR-004**: 系統必須維護專案列表，支持狀態（進行中/規劃中/已結案）切換與提示詞數量顯示
- **FR-005**: 系統必須將正式提示詞以 Markdown 檔案儲存於專案資料夾，包含 YAML Frontmatter 與內容本體
- **FR-006**: 系統必須在 Frontmatter 中保存至少：標題、專案、類型、狀態、模型、標籤、最後更新時間、備註
- **FR-007**: 系統必須提供提示詞列表，支援依專案與狀態篩選、關鍵字搜尋（標題/內容/標籤），並顯示更新時間
- **FR-008**: 系統必須提供 Markdown 編輯器與預覽，支援語法高亮與多種區塊（程式碼、列表、標題）
- **FR-009**: 系統必須提供兩種複製模式：完整複製（含 Frontmatter）與精簡複製（僅內容本體，排除元數據）
- **FR-010**: 系統必須提供片語庫管理（新增/編輯/刪除/搜尋/分類顯示），並允許將片語插入編輯器游標位置；UI 與 API 行為需一致且即時刷新列表
- **FR-011**: 系統必須追蹤片語使用次數與最後使用時間，並在片語詳情或列表中呈現
- **FR-012**: 系統必須在偵測檔案系統變動（外部修改、移動、刪除）時提示使用者採取行動（重新載入、重新定位、保留當前編輯）
- **FR-013**: 系統必須驗證檔名合法性並自動處理禁用字元，避免寫入失敗
- **FR-014**: 系統必須能讀取並顯示外部工具直接編輯後的 Markdown 檔案，保持內容同步
- **FR-015**: 系統必須在 YAML Frontmatter 損壞時以純文字模式顯示並標記需修復，允許使用者重新保存為有效檔
- **FR-016**: 系統必須在啟動時載入預設根路徑，若路徑不存在需引導使用者設定新的根路徑
- **FR-017**: 系統必須在搜尋結果過多時限制顯示數量（超過 1000 筆僅回傳前 1000 並標記截斷）並提示使用者收斂搜尋條件
- **FR-018**: 系統必須於 UI 呈現今日變更報告入口及新增提示詞快捷操作，對應 UI Prototype 的頂部操作區
- **FR-019**: 系統必須提供專案新增/編輯/刪除 UI 與 API，並同步刷新提示詞計數與選取狀態
- **FR-020**: 系統必須允許直接新增提示詞（不經草稿）、刪除提示詞，以及在 UI 編輯 Frontmatter（標題/狀態/類型/模型/標籤/備註）
- **FR-021**: （併入 FR-010）不再獨立驗收；僅保留編號供追蹤，所有片語 CRUD/UI/API 行為依 FR-010 規範驗收並即時反映列表與使用次數
- **FR-022**: 系統必須在設定頁提供 rootPath 輸入與儲存，RootPathAlert 需導向設定頁以補齊路徑
- **FR-023**: 系統必須提供草稿刪除操作，執行後列表與收件匣計數立即更新
- **FR-024**: 系統必須提供三欄分隔拖曳並將寬度持久化（localStorage），重新整理後保留設定
- **FR-025**: 系統必須提供專注編輯模式，隱藏中欄並最大化右側，切換不影響游標與寬度記憶
- **FR-026**: 系統必須提供提示詞列表 Pin 開關，預設 Pin=ON，狀態存 localStorage 並跨專案/重整沿用；Pin OFF 時點選後自動收合列表，左欄再點同專案或快捷鍵/按鈕可召回並保留 scroll 與選取
- **FR-027**: 系統必須支援提示詞列表批次操作（多選）與三點選單動作：重新命名、複製/另存為、移動、歸檔、刪除；危險動作需清楚區隔
- **FR-028**: 系統必須將片語面板改為右側 Drawer（按鈕/Alt+S 開啟，Esc/overlay 關閉），開關不得重新 mount 編輯器且插入後保持游標位置
- **FR-029**: 系統必須將前言區塊改為預設收合的 accordion，並提供摘要；標題列需 sticky 並顯示儲存狀態與快捷操作
- **FR-030**: 系統必須提供 CRUD Undo/snackbar 與危險操作二段式確認，Undo 時間窗 5–10 秒
- **FR-031**: 系統必須支援快捷鍵：Alt+L（列表顯示/隱藏）、Alt+P（Pin 切換）、Alt+N（新增提示詞）、Alt+Shift+N（快速草稿）、Alt+S（片語 Drawer）、Ctrl+K（全域搜尋）、Ctrl+Shift+C（精簡複製），且避免與瀏覽器衝突
- **FR-032**: 系統必須將全站字級放大 +2px 並調整行高/間距以避免裁切，符合 WCAG Text Spacing 原則

### Non-Functional Requirements

- **NFR-001**: 應用允許匿名遙測與更新檢查，預設開啟；應提供使用者在設定中停用遙測或更新檢查的選項
- **NFR-002**: 本機資料（草稿/提示詞/設定）存放於使用者目錄下的隱藏資料夾，沿用作業系統帳戶權限，預設不施加應用層加密

### Key Entities *(include if feature involves data)*

- **Project（專案）**: 業務或任務容器，包含 id、名稱、狀態、提示詞數量、最後更新時間；關聯多個 Prompt
- **InboxItem（收件匣草稿）**: 尚未歸檔的靈感，包含 id、標題、內容、提示/備註、建立與最後編輯時間
- **Prompt（提示詞）**: 正式檔案，包含 id、專案參照、標題、類型、狀態、模型、標籤、內容本體、備註、更新時間
- **Snippet（片語）**: 可重複使用的片段，包含 id、名稱、分類、內容、使用次數、最後使用時間
- **Settings（設定）**: 應用層設定，如根目錄路徑、預設篩選與顯示偏好

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者自啟動應用到開始輸入草稿的時間 ≤ 5 秒
- **SC-002**: 草稿轉正為正式提示詞並寫入檔案的整體流程時間 ≤ 30 秒
- **SC-003**: 精簡複製動作（點擊按鈕到內容可貼上）完成時間 ≤ 3 秒（內部目標 < 150ms）
- **SC-004**: 標籤或關鍵字搜尋返回結果的時間 ≤ 2 秒（在 1000 筆提示詞規模下）
- **SC-005**: 自動保存間隔內的編輯內容遺失率為 0（重啟後可完整復原）
- **SC-006**: 外部修改檔案後，應用在 5 秒內偵測並提示處理選項
- **SC-007**: 片語搜尋與插入完成時間 ≤ 10 秒（含搜尋、點擊、插入）
- **SC-008**: 啟動並載入包含 50 個專案、500 個提示詞的資料集時間 ≤ 5 秒
- **SC-009**: 首次使用（捕捉草稿→轉正→複製精簡版）的成功率 ≥ 80%（不需查閱教學；可設定更高內部目標於檢核文件）
- **SC-010**: 使用者回報的因介面卡頓導致流程中斷比例 ≤ 5%
- **SC-011**: 拖曳三欄後重新整理仍保留寬度設定，誤差 <5% 並可於 150–250ms 內完成列表收合動畫
- **SC-012**: 專注模式切換不丟失游標與未儲存編輯，恢復後寬度設定一致（±5%）
- **SC-013**: 快捷鍵成功率 ≥ 95%（Alt+L/P/S/N/Shift+N、Ctrl+K/Ctrl+Shift+C），且無瀏覽器衝突回報
- **SC-014**: CRUD 危險操作提供 Undo（5–10 秒）且誤刪復原成功率 ≥ 95%
- **SC-015**: 前言 accordion 預設收合且展開/收合不重置編輯器內容或游標，錯誤率 0
- **SC-016**: Inbox 淨空狀態需清晰呈現並引導下一步，不因收件匣空白造成誤解；可用性檢查通過
- **SC-017**: 編輯器 Undo/Redo 容易被發現且可用，快捷鍵可用率 ≥ 95%，無破壞焦點行為
- **SC-018**: Accordion 展開/收合快捷鍵或操作提示可被發現且行為一致，無錯位
- **SC-019**: 常見錯誤（檔案寫入失敗、搜尋截斷、衝突提示）文案可理解且行動導向，使用者可在單一步驟內採取修正
- **SC-020**: 長操作（搜尋 1000+、大量載入）期間有明確忙碌/進度指示，避免誤判為卡死，觀察無「卡死」回報

### Success Criteria 驗證方式

- **SC-001, SC-008**：以預載 50 專案/500 提示詞資料集進行啟動與列表載入量測，記錄啟動至可編輯時間；納入 perf-checks 腳本並附結果。
- **SC-002**：實際執行「草稿→轉正」流程並量測耗時（含寫檔），重複三次取平均；結果寫入 perf-checks。
- **SC-003, SC-007**：透過自動化測試量測精簡複製與片語插入至完成的耗時；於 perf-checks.md 紀錄（SC-003 驗收 ≤3 秒，內部目標 <150ms 於 perf-checks 註明）。
- **SC-004**：以 1000 筆提示詞資料集執行搜尋 p95 量測，超量情境驗證截斷旗標；結果納入 perf-checks.md。
- **SC-005, SC-012**：整合測試驗證自動儲存/專注模式切換後內容與游標復原；必要時加入延伸測項。
- **SC-006**：模擬外部修改後 5 秒內偵測提示的自動化流程，紀錄符合率。
- **SC-009~SC-015**：以整合測試或手動腳本驗證快捷鍵成功率、Pin 收合 SLA、Undo 成功率、accordion/拖曳寬度持久化；結果填入 perf/ux 檢核文件。
- **SC-016~SC-020**：以 UX 檢核腳本驗證 Inbox 淨空可見性、Undo/Redo 易發現性、accordion 快捷鍵一致性、錯誤敘述可理解性、長操作忙碌指示；將結果填入 docs/ux-checks.md 並納入 T062/T063 對應表。
